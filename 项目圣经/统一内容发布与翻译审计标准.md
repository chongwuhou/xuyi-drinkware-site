# XUYI 统一内容、翻译与媒体发布标准

这是人工、任意 AI、localGPT、脚本、GitHub Actions、CMS 后台和所有后续自动化共用的最终标准。具体执行顺序按 [XUYI 网站统一执行手册](../docs/XUYI_OPERATIONAL_RUNBOOK_ZH.md)。

## 1. 真源和字段所有者

| 内容 | 唯一真源 | 禁止作为发布源 |
| --- | --- | --- |
| 产品、Blog、评价、翻译、页面 SEO、发布状态、语言配置 | Cloudflare D1/CMS | dist、线上 HTML、聊天记录、临时 JSON |
| 图片、封面和媒体对象 | Cloudflare R2；引用、ALT、语言和审核关系写入 D1 | 本地文件、手工替换 URL、未核验对象 |
| 模板、组件、渲染器、测试和发布规则 | GitHub 源码 | 直接修改生成页面 |
| sitemap、静态页面和 build-meta | 标准构建产物 | 直接编辑后发布 |

产品数量、语种、分类、路由、分页、字段和公开状态必须从 D1/config 读取。不得在代码、文档、界面或测试中把当前数量写成业务事实。

## 2. 人工和 AI 统一边界

- 人工通过正式后台编辑；AI 通过已鉴权的正式 HTTPS API。两者写入同一套 D1/CMS 字段和 R2 引用。
- AI 只能做草稿、翻译初稿、组织、查重和审计，但不能猜测容量、材质、认证、MOQ、交期、客户案例、评价或图片事实。
- 正式写入前必须有审核状态和本次明确发布授权；没有授权只能只读或保存草稿。
- AI 发布文章不得操作浏览器，不调用 Google API，不使用日期专用脚本，不直接写 dist、线上 HTML、Pages 成品或 R2 缓存。
- 禁止脚本、插件、自动化或 AI 直接写 dist、线上 HTML、Cloudflare Pages 成品或 R2 缓存来冒充发布。
- 所有写入必须幂等、条件化、可回滚：相同内容复用；内容冲突返回 409 并停止；不覆盖人工编辑、不重复插入、不删除业务数据。
- 任何计费、额度、试用赠金或费用不明确的 API 都禁止调用；密钥只能在受控 Secret 中使用，不能写入仓库、D1、日志或聊天。

## 3. 通用发布顺序

1. 读取 D1/CMS 当前记录、字段所有者、语言配置、发布状态和 publish revision。
2. 读取真实产品、文章、评价和媒体来源，建立待审核内容；先做事实核对、主题去重和关键词蚕食检查。
3. 文章按 Blog 编辑标准完成独立主意图、实质章节、FAQ、采购清单、决策矩阵、产品内链和相关阅读；各配置语种独立翻译。
4. 图片先检查场景、版权/来源、尺寸、格式、SHA 和 URL，再上传 R2；R2 成功后才把路径、ALT、语言和引用关系写入 D1。
5. 通过通用 D1/CMS API 或正式后台条件写入，读取回执、写入数量、语言集合和 revision。
6. 已发布 Blog 的表格、FAQ、内链或翻译缺陷，必须使用条件式 D1/CMS 迁移修复；迁移必须具备“旧值精确匹配、正确值幂等跳过、其他值拒绝覆盖”三种结果，不能只修改静态构建产物。
7. 从 D1 snapshot 进行两次干净构建，运行语法、真源、内容、媒体、路由和多语回归测试。
8. CI 和部署成功后，核对 build-meta、D1 revision、R2 对象、详情页、列表分页、canonical、hreflang、OG、sitemap 和代表 URL。

## 4. Blog、产品和多语质量

### Blog

- 标题、H1、Meta、首段、章节、FAQ 和 CTA 只服务一个明确的 B2B 长尾问题；优先口语化、问句式和句子式搜索。
- 可自然加入已核实的容量 ml/审核 oz、材质、颜色、盖型、OEM、定制、批发和采购词，但不堆砌关键词或制造事实。
- 正文必须有真实产品详情链接和人工挑选的相关阅读；链接要服务采购决策，不能用导航、分类或自动补链凑数。
- 主题地图至少记录 slug、intent、audience、funnelStage、primaryKeyword、coveredQuestions、evidenceSources、supportingLinks、canonicalRole 和 lastReviewed。
- 已发布文章只做一致性复核，不自动删除、合并、改 URL、canonical 或发布日期；整合必须另行授权并准备回滚方案。

### 产品和 SEO

- 每个型号 × 当前配置语言独立维护 Title、H1、Meta、OG、正文和 ALT；最终值读取 D1 的产品 SEO/内容记录。
- 容量以资料中的 ml 为准；oz 只能使用审核后的换算档位。材质、颜色、认证、MOQ、尺寸、交期和厂家能力没有来源就不写。
- 产品标题和 H1 需自然体现差异化产品词、采购/厂家词、材质、颜色和容量，但不把未确认的定制能力写成现有 SKU 事实。

### 翻译审计门禁

- 目标语言、发布资格和排序只来自 D1 language_config 的 enabled + publishReady 集合。
- 每个语种都要有完整 Title、Meta、正文、章节、FAQ、矩阵、产品链接、相关阅读、ALT、按钮、面包屑和结构化数据；不能只翻标题、只拼摘要或用英文冒充译文。
- 多语言列表使用同一份 D1 已发布顺序；分页、卡片数量、canonical、hreflang 和 sitemap 按当前配置验收。
- 发现高置信度漏翻译、串语、英文锚文本或同 URL 重复内链时，停止发布并回写 D1/CMS；禁止在构建后替换 HTML。

### GEO 内容

- 先直接回答问题，再给参数、判断条件、操作步骤、适用/不适用边界和采购下一步。
- 优先清单、对比表、决策树、FAQ、实测过程和可核验数据；真实案例、第三方资料和外部权威链接必须有来源或明确示意披露。
- 不输出字符截取、半句拼接或统一套话组成的“证据区”。GEO 证据、citation 和 JSON-LD 只能由文章自身已审核的 evidence/研究/正文字段生成；没有来源就不生成，不能为了达标伪造数字、引用或区块。
- 文章章节中的长段落按正文语义去重；同一长段落不得在多个章节重复。重复防护必须位于 D1/CMS 共享渲染器和发布门禁，不能在生成后的 HTML 上做一次性替换。
- FAQ 标题、可见问答和 FAQPage 必须三者一致：没有完整可见问答就不输出标题和 FAQPage；发布批次按现行标准保存 4 组完整 FAQ。
- 任何表格/清单的“检查项—证据—动作”三列必须逐行对应，修复应写回审核源数据或由有条件的源渲染规则统一处理，不能用页面后处理掩盖错位。
- 不发布空泛批量生成内容，不把 AI 生成的图片、客户、认证、订单或测试当作真实证据。外部平台分发必须经授权并回溯到 D1 事实源。

## 5. 失败、回滚和完成判定

- R2/D1 响应超时或不明确：先只读核验对象、记录和 revision，确认未写入后才重试；禁止盲目重复 POST。
- D1/R2 已写入但构建失败：保留正式数据，只修复模板、测试或构建输入，不重复写内容。
- 线上异常：记录 URL、HTTP、build SHA 和 revision，从 D1/R2/Git 正式历史回滚并重新构建；禁止用旧 dist 覆盖线上。
- 没有完整的 D1/R2、CI、revision 和线上 URL 证据，只能标记草稿、待审核、待构建或待验证，不能写“已发布”。

这套规则不依赖当前文章、产品或语言数量。任何新增功能先补充通用字段所有者、幂等条件、回归测试和回滚方式，再接入生产流程。
