# XUYI 架构与数据真源

## 技术层

- Cloudflare Pages：部署预渲染 HTML/CSS/JS/图标，不运行常驻应用服务器。
- Pages Functions：使用现有 `functions/` 提供询盘、D1 Blog、站点设置和 Admin API。
- D1：旭一 Blog、询盘、后台安全、网站联系人及语言设置、发布修订记录的生产数据真源。
- R2：现有真实产品、图库、集团已授权图片和 Blog 上传封面；静态图片走本域 `/media/`。
- 版本化 `templates/site/`：四个共享结构模板；导航链接仍由旭一的业务数据生成。
- `scripts/build_release.py`：把 `build.py` 生成的网页和允许公开的资源组装到 `dist/`。
- `scripts/preflight.py` 与 `scripts/test_release.py`：品牌/绑定/SEO/链接/文件数/模板一致性门禁。
- `.github/workflows/publish-xuyi.yml`：对标德玛隆的定时 D1 revision 检查和 CI 构建/部署控制器，依赖本仓库专用 GitHub Actions 凭据。

## Blog 多语言列表顺序

- 英文 /blog/ 实时页由 functions/blog/[[path]].js 调用 listBlogPosts(db,'published')，当前统一 SQL 为 `ORDER BY COALESCE(published_at, updated_at) DESC, slug ASC`：先按实际发布日期倒序，历史缺失发布日期才回退更新时间；人工编辑不会改变文章在列表中的发布时间顺序。
- 非源语言的 `page:/blog/` 翻译记录保存各自的本地化卡片文案和 HTML，但语种集合必须从 D1 `language_config` 的 enabled/publishReady 记录读取；完整卡片顺序必须与同一次英文实时 D1 查询返回的全部 slug 顺序一致。
- 批量发布可先写入新文章和本地化卡片，但追加到列表末尾不是最终排序。写入后必须重新读取完整 D1 已发布列表，按返回结果重排所有当前配置语言的卡片块，只调整卡片位置，每张卡片内部 HTML 必须保持原样。
- 禁止按当天批次 hardcode slug 置顶，禁止直接改写静态 HTML 或 dist/。若卡片缺失、重复、额外或与 D1 集合不一致，必须停止发布；上线前后都要核对 D1 当前所有 publishReady 语种的完整 slug 顺序。

## 批量发布与调度边界

- 正式批量 Blog 入口只有 `/api/admin/blog-batch`。不保留日期接口、日期来源注册或历史 HTML 拼接逻辑。
- 新增、重跑、排序修复都先读 D1 当前记录和语言配置，再进行条件写入；同内容重跑幂等，人工修改冲突时停止并保留人工值。
- 定时队列不以固定语言数组判断完成；新增后台语种只要通过资源审核并置为 publishReady，就由同一套队列和构建流程纳入。

## 无回归保证

迁移基线生成时 136 个预渲染页面 SHA256 全部未变，产物与历史根目录 HTML 一致；上线后按照 D1/R2、SEO、FAQ、联系人和不同语言分层回归。

## 隔离要求

生产构建只允许 `xuyi-drinkware-site`、`xuyi-drinkware-d1`、`xuyi-drinkware-r2`。

Blog 已上线内容的结构性数据修复必须走条件式 D1/CMS 迁移：读取当前正式记录，精确匹配已确认的缺陷后才更新；已修复则幂等跳过，发现人工新改内容则失败并保护原值。不得把一次性修复写成静态 HTML 或模板兜底。生产迁移使用 Cloudflare D1 正式 API 的参数化查询与事务批量写入，不依赖页面部署时序。
禁止把德玛隆 `CATALOG_DB`、`MEDIA_BUCKET`、`MODEL_PAGES_BUCKET`、品牌、产品数据、密钥引入旭一。
